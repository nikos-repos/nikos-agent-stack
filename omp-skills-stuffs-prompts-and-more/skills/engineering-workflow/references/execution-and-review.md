# Compose execution and repair claims

Read when work spans a caller/substep boundary, a review/repair cycle, or a disputed completion claim. Use existing task and evidence records; this is not a second coordinator or machine schema.

## Establish the actual candidate and owner

Resolve the outcome, authority, candidate/base revision, existing proof, remaining work, and owner of the next stage. Include relevant new/generated files that a convenient diff omits. For PR review, match local evidence to the actual PR revision; a branch name or tracker state is insufficient. After integration, assess the combined candidate and changed interface effects.

Choose ordinary change, standalone review, simplification survey/change, existing factory route, or caller-owned substep. A substep returns its scoped result, raw proof, and unresolved claims to its caller. It does not independently restart simplification, review, publication, and learning already owned upstream. Existing factory ownership, schemas, checks and barriers remain binding.

## Disposition before repair

| Claim state | Next action |
|---|---|
| Required behavior is demonstrably wrong | Repair its owning cause and revalidate affected claims. |
| Required behavior lacks adequate proof | Obtain the smallest decisive proof; change product code only if evidence exposes a defect. |
| A material requirement or finding is uncertain | Investigate the missing fact within the task's budget; keep the required claim unresolved if it remains unknown. |
| Optional preference, duplicate, or stale finding | Explain the disposition without making it compulsory scope. |

Keep severity, confidence, and repair size separate. Validate a diagnosis independently of its suggested remedy. A real defect found late remains relevant even if an earlier reviewer should have caught it. Missing proof is not proof of failure or success.

## Preserve valid evidence

After a repair, identify which prior claims depend on changed code, inputs, environment, or assumptions. Rerun that affected region and any combined integration boundary; retain unrelated valid evidence. A summary/receipt-format change need not rerun expensive computation. A small authorization or identity change may invalidate many claims.

Classify a blocked step by the guarantee it protects. Cosmetic metadata can be reconstructed from authoritative evidence. Leases, source identity, frozen inputs, side-effect receipts, and required gates need reconciliation through their real owner; never bypass them for forward progress. Uncertain external effects remain under the operating loop's reconcile-before-retry rules.

For warranted independent review, provide the actual candidate, requirements, settled user constraints, and raw proof. Keep the implementer's persuasive account and prior reviewer verdict separate from the initial independent assessment. Multiple models repeating one premise do not constitute an independent behavioral oracle. Recheck surviving and newly affected claims; do not reset every review after every edit.

Stop repeating work that produces no new evidence. State the remaining required blocker, owner, and next decisive action, preserving valid work and the original budget. A fixed round quota cannot excuse a required defect; time or budget exhaustion cannot turn missing acceptance into completion. Respect actual native terminal states.
