# OMP-DEV control and operations guide

This guide describes the proposed release and distinguishes its instructions from mechanisms inspected on the current host. Release inventory records exact bytes and versions. Reading a file or matching its hash does not establish that a running parent or child loaded it.

The established design rule remains: place a control on the earliest surface that can actually observe the violation. A regex can recognize bounded byte patterns; it cannot establish user intent, the value of a test or whether a shim is needed by a consumer. Keep those judgments with their policy/procedure owner and independently check their outcomes.

| Layer | Owner and source | What it does; limit |
|---|---|---|
| L0 routing | Native OMP config/model catalogue and agents/*.md | Resolves roles/models, tools and skill autoload at session/dispatch; declared config and effective load are distinct |
| L1 persona | APPEND_SYSTEM.md | Identity, judgment priorities, style and a compact routing/control index; advisory |
| L2 sticky judgment | RULES.md | Always-apply near-turn rules; advisory, including test policy and evidence honesty |
| L3 write interrupt | rules/*.md and native rule loader/TTSR | Interrupts matching scoped generated bytes; one-shot suppression requires the existing stop backstop, and regex alone does not prove correct loader bucketing |
| L4 native guard | Native config/tool implementation | Seen-line edits, streaming checks and supported tool constraints; only configured supported keys have their implemented effect |
| L5 advisor | WATCHDOG.yml and native advisor routing | Terra inspects current candidate/criterion/violation evidence and can steer or interrupt under native severity semantics. Evidence labels are prompt conventions; native validates note and severity |
| L6 delivery | gate-checker and configured gate policy | Observed command/claim checks, manifests, provenance, interrogation, cooperative mutation leases and delivery stop decisions; warnings or continuation release are not a successful proof |
| L7 durable workflow | omnipotence plus registered versioned processes/guards | Owns run/effect/fence/pin/history and recovery. Installed blueprint files do not prove registration; factory gatekeeper semantic checks cover what the guard does not parse |

Skills are procedures invoked within this stack, not a new L8 enforcement service. [The routing guide](skills/USER_GUIDE.md) selects their owner. The source-owned gate command ledger remains the single command-observation basis; commands_run in factory results is still a self-reported claim. No duplicate command database is introduced.

## Release and policy changes

The proposed RULES testing line replaces the old ban on unrequested new test files and compulsory security-memo update with behavior-driven, authorized verification and material-finding recording. APPEND, RULES, TDD, factory-build and this guide must be selected coherently. Existing factory ceilings, cadence, doubles rules, escalation and mandatory risk/breakpoint response identity stay binding. An accepted product gate does not authorize a distinct external action.

The npm package ships the three extensions, two binaries, explicit public exports, advisor file and a limited documentation set. It does not ship the complete skills/prompt/config/blueprint installation. The release plan supplies a separate source-to-install mapping. Do not infer complete installation from npm link/install or a copied skill root. Advisor installation merges the packaged Terra entry while preserving other advisor entries; verify the resulting instructions and keep a rollback copy because YAML comments are not preserved by that installer.

Before activation inventory maintained sources, installed sources, project overrides, native source/version, configuration/model/agent metadata, rules, guide paths and the selected blueprint/process/guard/gatekeeper. Capture parent and child effective loading independently of file hashes. Preserve original factorySkillsRoot input and same-root preflight evidence. If different global guidance cannot coexist for old and new runs, drain/reconcile old runs under unchanged sources before activation. Never rebind an active run to new bytes to make a hash pass.

## Ordinary operation and recovery

Use the smallest suitable route before factory admission. Keep one owner for acceptance and one admitted writer in a shared integration checkout. Independent work may proceed within actual capacity; session task caps are not host quotas. Check current integrated output, affected consumers and raw proof. A task report, gate release, CLI exit zero or completed run does not itself mean delivered.

Gate-checker is the only session_stop registration and composes delivery → questionnaire → omnipotence via the existing write-once slots. While a questionnaire is pending its native allowlist applies; a successful ask clears transport policy but does not prove a semantic answer or durable approval. After session reset inspect unanswered requirements and redeclare where necessary.

Recover original job/run/effect/attempt/source identity before retry. Both-null dispatch timestamps permit the engine's supported undispatched recovery; intent-only or acknowledged unknown work needs reconciliation. Keep unresolved detached work owned and quarantined until terminal status, late cleanup/release and external effects are settled. Forever is session-hosted and is not a daemon or a hard spend cap. Use the actual CLI guide for supported grammar and inspect result payloads.

Factory failed probes retain exact raw evidence under .factory/probes/history/<task-id>/<attempt-number>/ with an explanatory context.md. The accepted canonical log contains only the latest complete grammar-conforming pass. History does not enter the closed result schema or become a second authoritative command ledger. New-project owns decisions.md writes; phase workers return audit notes. The current five finish records and six gatekeeper checks remain exact.

## Known gaps, disposition and scope

| Finding from the old guide | Present disposition |
|---|---|
| Missing factory guides in routing/CLI text | Replaced with the actual maintained new-project and phase contracts; no missing files invented |
| Missing skill-dev linter | Removed its nonexistent invocation; native-format metadata and reference inspection remains advisory. Release validation scripts are supplied by the revision |
| Missing standalone paper-to-gpui | GPUI routes to its existing local Paper reference and capability checks |
| terra-high and claude have no discovered automatic caller | Retain as manually selectable profiles pending operator usage review. Absence of a caller is not removal evidence |
| claude front matter names Sol but body dispatches Claude | Two execution layers: the wrapper agent model and the downstream CLI model are different settings. Resolve actual wrapper and target model before use; do not change a provider merely to match the profile name |
| qwen3-1.7b local memory selection | Inspected native model catalogue explicitly marks that export unsupported. The selected memory mode and fallback have not been exercised; block that local inference path until a supported configuration is tested. Do not claim all mnemopi paths fail |
| compaction.methodOrder / composer.shape | Present in inspected config, absent from inspected native schema/search. No supported effect established; target owner verifies consumers before removing or replacing the keys |
| GatePolicy omitted subagentClaim | Stale finding: current source uses ReturnType<typeof policyFor>. Do not reintroduce a fixed defect |
| AGENTS.md claimed at the agent root | Absent on inspected host. Auto-loaded context is advisory regardless of where shown in a table; discover actual context sources per target |
| commands_run is self-reported | Retained explicit limitation. Future persistence belongs to the existing gate evidence owner and needs a justified consumer/identity contract |
| Probe grammar enforcement | Gatekeeper convention plus strict path/nonempty guard check; no full deterministic parser is claimed. A future guard hardening must preserve versioned old-run semantics |

Historical enforcement ADRs remain authoritative design context in the repository's docs/maintainers/adr directory. The August 31 branch inventory is a dated snapshot, not current permission or a current remote topology claim. Recheck exact refs before any future integration/push.
