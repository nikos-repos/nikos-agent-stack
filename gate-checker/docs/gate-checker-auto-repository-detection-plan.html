automatic repository detection

bind a request to the first repository that its tool activity enters, before mutation, then replace the misleading degraded label with the capability label low: no git.

decision

chosen direction: keep one request baseline, but allow its repository scope to bind lazily from tool context while the request is still in no-git operation. perform detection in the existing tool_call handler, before any tool side effect. reuse capturebaseline; do not parse shell command text and do not add a watcher, timer, dependency, or omp core patch.

this fixes the ownership error: agent_start currently captures only ctx.cwd. a session started in a global directory therefore stores a null git baseline for the full request, even when later tools use a repository path. the tool event is the earliest existing seam that exposes the effective operation path before a mutation.

the configured engagement level remains separate from repository capability. for example, medium policy outside a repository displays gate: medium · low: no git. repository discovery removes the capability suffix; it does not change the saved policy to low.

problem and success criteria

current failure

  • a request starts outside git, so capturebaseline(ctx.cwd) returns a null commit and repository root.
  • the request keeps first-touch hashing for its full lifetime because repository detection runs only at agent_start.
  • later tool calls can target a repository through an explicit working directory or an absolute file path, but the extension does not reconsider its scope.
  • the status and telemetry call this valid fallback behavior degraded, although the gate still checks watched edits and can run verification.

measurable success

  • a session started outside git binds to a repository before the first repository mutation when a tool supplies that repository through its working directory or path.
  • the final gate uses the captured repository baseline, repository root, dirty-file exclusion, lease, verification working directory, and commit policy exactly as a session started in that repository would.
  • no-git operation remains available and uses the exact user-facing label low: no git; no user-facing text calls it degraded.
  • source tests, embedded checks, and the extension wiring probe pass from the repository and from the copied live extension.

proposed runtime behavior

  1. start the request and capture the normal baseline from ctx.cwd.
  2. if no repository exists, show low: no git and retain first-touch hashing.
  3. before each tool runs, derive bounded candidate directories from explicit tool context.
  4. use capturebaseline on candidates until one returns a repository root and commit.
  5. bind once, journal the binding, acquire the repository lease, and use git scope at session stop.

candidate precedence

sourcederivationreason
input.cwdresolve it against ctx.cwdcovers bash and other tools that declare their effective working directory.
input.pathresolve the file path, then use the nearest existing parent directorycovers read, write, and edit calls that use absolute or repository-directed paths.
ctx.cwduse it as the final candidatecatches a harness working-directory update without depending on a new event.

deduplicate candidates and stop after the first successful baseline. do not scan parent trees in javascript; git already resolves the top level. do not inspect free-form shell commands such as cd …. omp tool conventions already provide an explicit working-directory field, and command parsing would be incomplete and unsafe.

binding invariants

  • bind only while the active request has no git baseline.
  • run binding before lease enforcement and before the target tool executes.
  • set the baseline commit, baseline dirty paths, baseline snapshots, and repository root as one state transition.
  • retain first-touch snapshots already collected outside the repository. at final adjudication, merge their no-git additions with the git scope instead of dropping earlier evidence.
  • after binding, continue first-touch snapshots only for write or edit paths outside the bound repository.
  • never rebind to a second repository during the same request. record a warning-only cross-repository limitation and leave the first repository authoritative.
  • restore the normal arming status immediately after a successful bind.
known ceiling: a bash command can mutate an unrelated path that neither its explicit working directory nor a path-bearing tool exposes. the current no-git implementation cannot prove such changes either. do not add shell parsing or filesystem watching for this update; add broader workspace ownership only if observed failures justify it.

acceptance checks

primary test seam: extend the existing end-to-end wiring probe. its no-git cases already model the required ordering: agent_start, then pre-effect tool_call, then mutation, then session_stop.
  1. working-directory discovery: start the handler in a non-git temporary directory. send a mutating tool call with input.cwd set to a temporary repository. mutate after the hook. assert that repository scope, verification directory, and status use the repository.
  2. path discovery: start outside git. send a write or edit call with an absolute path inside the repository. assert that binding occurs before the file changes and newly added forbidden text is detected through git scope.
  3. dirty baseline: dirty one repository file before discovery, then modify another after discovery. assert that the pre-existing dirty path stays excluded and the new path is adjudicated.
  4. fallback: target only a non-git directory. assert that first-touch checking still works and the status contains the exact text low: no git.
  5. mixed evidence: make a watched non-git edit, then bind to a repository. assert that final adjudication does not discard the earlier watched addition.
  6. single binding: target a second repository after the first binding. assert that the baseline does not change and the request reports the bounded limitation without corrupting the first scope.
  7. journal restore: reduce request-start plus repository-bound events. assert the active state contains the bound baseline and dirty set.
  8. telemetry cutover: summarize one historical degraded record and one new no_git record. assert no_git_runs equals two and new console output says low: no git runs.
  9. source cutover: search runtime and guide text for degraded. allow only the historical ledger input string and a migration-focused test fixture.

non-goals and open questions

out of scope

  • changing the low, medium, or high engagement policy matrix.
  • parsing shell command text to discover cd targets.
  • supporting multiple authoritative git repositories in one request.
  • adding filesystem watchers, background polling, a dependency, an installer program, or an omp core patch.
  • changing babysitter gate semantics; this update targets the automatic extension lifecycle.

resolved questions

  • does no git mean broken? no. it remains valid lower-evidence operation and receives the requested label low: no git.
  • does repository discovery change engagement policy? no. policy and repository capability remain independent.
  • when does binding happen? before the first path-bearing tool effect, at the existing tool-call seam.
  • which repository wins? the first successfully detected repository for that request.
