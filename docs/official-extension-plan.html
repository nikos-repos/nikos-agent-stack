approved direction

official omp extension conversion

replace commit-bound omp source patches with one conventional plugin package that installs through the native omp plugin manager.

decision: publish the repository root as nikos-agent-stack. declare public extension entries in package.json#omp.extensions. bundle the terra task profile through the plugin agent discovery convention. remove format-patch distribution.

problem

  • the questionnaire and advisor packages currently require exact omp source commits and git am.
  • that process forks the user harness, conflicts with later omp changes, and cannot use the plugin manager rollback and enablement model.
  • the gate checker already uses the supported extension api but installs by manual file copy.

public-api boundary

moduleextension-native replacementintentional change
gate checkerload gate-checker/index.ts as a declared extension.no behavior change.
ask questionnaireload a policy extension that detects new-project prompts, injects ask guidance, and blocks other tools until the native ask tool completes.use omp's native ask ui and transport instead of patched core files. no queue internals or forced tool-choice mutation.
terra advisorinstall agents/terra.md with read-only tools and a structured evidence output schema.terra becomes an explicit task agent. plugins cannot register a passive native advisor or write watchdog.yml.
compatibility rule: the package uses only documented plugin, extension, and agent discovery surfaces. exact native advisor cards, passive advisor interruption, and core queue control stay out of scope because omp does not expose those extension points.

implementation phases

  1. package contract: add public package metadata, npm file allowlist, two extension entries, and the terra agent profile.
  2. questionnaire policy: port only the new-project requirement into an extension with deterministic prompt detection and request-local state.
  3. verification: add focused tests for package contents, extension initialization, policy transitions, and local plugin linking.
  4. documentation cutover: replace every patch/base-commit instruction, remove patch artifacts, and document install, update, removal, behavior, and limitations.

acceptance

  • omp plugin link . discovers and enables the package.
  • the gate commands load from the installed package.
  • a direct new-project request cannot use another tool before one successful ask call.
  • the terra task profile appears in installed agent discovery and remains read-only.
  • bun run test passes from a clean repository.
  • no guide tells users to check out or apply an omp commit.

out of scope

  • publishing to npm or pushing to github.
  • changing omp core to add new extension points.
  • preserving behaviors that require private queue, advisor, or transcript-renderer internals.
