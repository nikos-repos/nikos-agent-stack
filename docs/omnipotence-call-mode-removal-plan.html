breaking change plan · schema 7 to schema 8

remove call mode without breaking replay or recovery

a clean public cutover with an append-only state migration. new runs use babysit; historical call events remain verifiable and recoverable.

decision

remove call from every public command, type, policy, and guide. migrate each stored call run to babysit by appending a canonical migration event. never rewrite an existing event or hash.

why this is the minimum correct change

public surface

delete the redundant mode

call and babysit currently share the same execution, breakpoint, and persistence policy. new users should see one supervised mode, not two names for the same behavior.

durable state

preserve immutable history

event hashes include the exact payload and previous hash. changing old payloads would replace the evidence chain. the migration must append a new fact instead.

runtime

resume active runs safely

the migrated projection uses babysit. active effects, fences, leases, sessions, turn counts, and process pins do not change because the two modes already execute identically.

recovery

keep doctor and repair valid

replay accepts call only as a historical event value and canonicalizes it to babysit. no public api can create another call run.

target contract

surface after cutover compatibility rule
slash command /omnipotence-call is not registered no alias and no deprecation command
cli --mode call is rejected new runs cannot persist call
public type orchestrationmode excludes call compile-time clean cutover
active projection all existing call rows become babysit same behavior, same run identity
historical events old payloads may still contain call read-only historical value; hashes remain unchanged
repair legacy event values replay as babysit internal decoder only, never a start mode

schema 7 to schema 8 migration

  1. fail closed before mutation

    run the existing event-chain and projection checks. if any hash, previous hash, or projection is invalid, leave schema 7 unchanged and stop migration.

  2. create a restorable backup

    use the existing vacuum into migration pattern and name the file .migration-v7-<timestamp>.

  3. canonicalize inside one immediate transaction

    for every row whose projection mode is call, update only mode and updated_at. keep ids, statuses, session bindings, effects, fences, leases, inputs, outputs, and turn counters unchanged.

  4. append an explicit migration event

    append run_mode_migrated with the complete canonical run projection, mode: "babysit", and previousmode: "call". use the existing event appender so the new event references the old tail hash.

    {
              "type": "run_mode_migrated",
              "payload": {
              "id": "<same-run-id>",
              "mode": "babysit",
              "previousmode": "call",
              "status": "<unchanged>",
              "fence": "<unchanged>"
              }
              }

  5. advance the schema only after all runs migrate

    set pragma user_version = 8 in the same transaction. a crash therefore leaves either the complete schema 8 migration or the original schema 7 state.

  6. verify the result

    require zero runs.mode = 'call' rows, valid event chains, matching projections, and a clean doctor report before normal engine work starts.

important invariant old events are never edited or deleted. the historical word call remains part of the verified record, while the newest projection event makes babysit the active truth.

implementation sequence

  1. storage contract first

    omnipotence/store.ts: add schema 8, the one-time migration, run_mode_migrated projection handling, and a private historical-mode decoder that maps event value call to canonical babysit.

  2. replay and repair

    omnipotence/store.ts: make doctor and repair treat run_created, run_status, and run_mode_migrated as run projection events. repair may read historical call, but it must always rebuild the current row as babysit.

  3. remove the public mode

    omnipotence/contracts.ts and omnipotence/processes.ts: delete call from the public union and policy table. the private historical decoder must not be exported.

  4. remove start surfaces

    omnipotence/index.ts: stop registering /omnipotence-call. omnipotence/cli.ts: reject --mode call through the reduced public mode list.

  5. migrate test fixtures

    replace generic executable-mode fixtures that use call with babysit. retain call only in schema 7 migration and historical replay fixtures.

  6. update user surfaces and version

    remove the command and mode section from the user guide, add a schema 8 upgrade note, and bump the package to 2.0.0 because a published command disappears.

tests and release gates

migration tests

  • terminal schema 7 call run becomes babysit.
  • active run keeps session, effects, fences, leases, and turn count.
  • database without call runs receives no migration events.
  • corrupt event chain blocks migration and remains schema 7.
  • migration creates a backup and is idempotent after schema 8.

replay and recovery tests

  • old event hashes remain byte-for-byte unchanged.
  • migration event links to the old tail hash.
  • doctor reports clean after migration.
  • repair rebuilds babysit from mixed historical and canonical events.
  • an active migrated run resumes without duplicate effects.

public cutover tests

  • /omnipotence-call is absent.
  • --mode call fails as unsupported.
  • public mode enumeration excludes call.
  • fresh databases cannot create call runs.

release gate

  • run the full omnipotence test set.
  • run doctor before and after a fixture migration.
  • restore the generated backup with the previous release.
  • start, pause, migrate, resume, and complete one real process.

release, failure, and rollback

condition required behavior
preflight verification fails do not create migration events; leave schema 7 untouched
transaction fails rollback all projection, event, and schema changes
post-migration doctor fails stop startup and direct the operator to the migration backup
operator rolls back the package restore the schema 7 backup; do not open schema 8 with the old release
migration succeeds continue the same active run under babysit policy
no compatibility alias the released surface has no call mode after the cutover. only the private event decoder recognizes the historical value, and only while replaying immutable records.

out of scope

  • no replacement mode.
  • no warning alias for /omnipotence-call.
  • no edits to old event payloads or hashes.
  • no changes to babysit, plan, yolo, or forever behavior.
  • no migration of process ids, versions, profiles, blueprints, effects, or sessions.
