first-screen recommendation

ship three integrity features first

proposalship only the three three-star integrity features in the first implementation tranche: path-scoped process-fenced state commit, daemon recovery receipt gate, and verified refinement transaction and guarded rollback.

  • sourced factthe decision bundle places seven two-star candidates in a ranked backlog and one one-star candidate on a watchlist, with the medium boundary set at the three three-star features.
  • inferencethe common seam is narrow machine-checkable evidence around mutation, recovery, and rollback; a generic gate or second service would add overlap rather than coverage.
  • proposalreuse existing leases, journals, ledgers, provenance, and gates; reuse native omp checkpoint, compaction, goal, provider, comm, and registry seams for later cards.

context source: prime agent release blog. pinned implementation evidence appears in each card and in the source list.

detailed candidate cards

candidate decisions

each card distinguishes sourced fact, inference, and proposal. every card has prime purpose, local remix, deterministic gate, scope boundary, failure mode, star rationale, and evidence links.

★★★first tranche · must add

path-scoped process-fenced state commit

sourced factprime combines process-start ownership fencing with atomic harness-state replacement; the stack already has lease, fence, journal, and conflict-blocking seams. prime ownership · stack lease

prime purpose

sourced factprevent pid reuse, stale ownership, and interleaved writes from corrupting daemon and harness state. prime harness state

local remix

proposalextend the existing stack lease record with process-start identity and an immutable resolved-path scope. add one reusable atomic json commit helper for current stack ledger and journal writers and future omp managed-harness adapters; compare the expected digest before rename. port no prime daemon or python runtime.

deterministic gate

proposalcanonicalize json, hash old and new state, acquire the existing path-keyed lease, compare identity, token, owner, fence, scope, and expected digest, write a pid-scoped temporary file, rename atomically, and record only digests and outcome.

scope boundary

proposaltouch lease.js, one process-identity helper, the existing journal adapter, and focused pid-reuse, stale-owner, malformed-state, digest-conflict, and atomic-rename checks. add no database, second lock, daemon, python runtime, or generic state service.

failure mode

inferenceplatform identity, unavailable identity, old records, path aliases, or rename behavior can block a writer; fail closed and emit recovery-required instead of reclaiming or rewriting. prime fence cases

star rationale

sourced factthree stars: it upgrades an existing stack lease and journal path, closes pid-reuse and lost-update holes, and makes every accepted write independently checkable. stack journal

★★★first tranche · must add

daemon recovery receipt gate

sourced factprime persists uncertain command and worker operations instead of replaying them; native omp already has retry recovery and replay-unsafe cancellation behavior, while the stack session-stop gate does not consume those states. prime receipt · native omp replay safety

prime purpose

sourced factmake interrupted or ownership-uncertain operations durable and explicitly non-replayable. prime worker journal

local remix

proposaldo not import prime's daemon. expose a small receipt from existing native omp turn and agent recovery transitions, map unresolved or replay-unsafe work to the stack's existing journal as recovery_hold, and make the current session-stop gate block until the receipt resolves.

deterministic gate

proposalidentify the session, operation, attempt, owner, and monotonic transition; accept only a fixed status enum; map malformed, stale, interrupted, or ownership-uncertain state to recovery-required; never ask the model to replay, kill, or waive it.

scope boundary

proposaladd one native omp recovery-event adapter and extend the stack's existing journal reducer and session-stop predicate. reuse current recovery behavior and storage. add no daemon, retry loop, replay engine, transport, worker supervisor, or second journal.

failure mode

inferencelate events, stale holds, or malformed receipts can block release; require a monotonic transition, bounded diagnostics, and explicit recovery resolution. native omp retry recovery

star rationale

sourced factthree stars: it connects two existing recovery and gate seams and prevents successful release while the runtime still reports uncertain work. stack session-stop gate

★★★first tranche · must add

verified refinement transaction and guarded rollback

sourced factprime records refinement baselines, applies proposals, and derives rollback operations; native omp already exposes write-capable managed-skill and memory mutations. prime apply path · native omp managed-skill tool

prime purpose

sourced factmake harness refinement application and rollback conflict-aware and visible in evidence history. prime rollback path

local remix

proposaldo not port prime's planner, python harness, or continual-refinement service. wrap native omp's existing manage_skill and memory_edit mutations with one stack transaction adapter: capture the target digest, run the existing mutation, reread the result, and record a bounded receipt. native omp memory edit

deterministic gate

proposalvalidate action, target type, id, scope, and schema; require the recorded after-digest; permit rollback only when the current digest still matches that after-state; otherwise record a non-applied conflict. use no llm judge.

scope boundary

proposaladd one gate-checker transaction adapter, one receipt schema in the existing journal or ledger, and focused hooks around the two native mutation tools. add no planner, crud store, python runtime, generic evaluator, or second rollback engine.

failure mode

inferencestale baselines, partial writes, schema drift, or newer edits can invalidate apply or rollback; fail closed and keep the conflict receipt observable. stack provenance

star rationale

sourced factthree stars: native omp already has the write surface and the stack already has provenance and journal seams; the missing guarantee is a small, independently checked transaction boundary around those exact mutations. stack journal

architecture flow

evidence moves through existing seams

medium-scope shipping boundary

keep the first tranche narrow

in the first tranche

  • path-scoped process-fenced state commit
  • daemon recovery receipt gate
  • verified refinement transaction and guarded rollback
  • existing lease, journal, ledger, provenance, and gate seams

ranked after core

  • goal completion attestation gate
  • validated compaction checkpoint
  • namespace-checkpoint attestation
  • bounded host-request authority
  • heartbeat dispatch health gate
  • bundled skill contract gate
  • first-class prime inference provider with attested metadata

outside this boundary

  • worker-health-aware agents view
  • generic retry, replay, or evaluator services
  • new lock, transport, scheduler, or release services
  • secrets, prompts, tool arguments, namespace values, and command output in receipts

proposalmalformed, unknown, stale, or unverifiable state becomes blocking recovery-required or an explicit non-applied result. sourced factthe bundle requires seam reuse and keeps deferred candidates outside the five-workstream baseline. stack gate policy

risk register

contain failure without model discretion

identity and lease portability

inferenceprocess identity and rename behavior are platform-sensitive; unavailable identity must fail closed, and old records need migration. ownership

daemon status races

inferencestatus can race journal append and stale busy records can block release; use fenced snapshot, monotonic marker, and recovery-hold. recovery

refinement side effects

inferencepython imports can have side effects and rollback must not overwrite newer edits; constrain inspection and use current-state preconditions. refinement

receipt data exposure

proposalstore ids, hashes, status, and bounded outcomes only; exclude prompts, arguments, credentials, command output, and namespace values. provenance

deferred portability and timing

inferencedill portability, cooperative cancellation, heartbeat clock skew, and strict compaction formats can reduce availability or freshness; keep out of first tranche. restore

migration and compatibility

inferenceold history, scheduled files, dynamic skill layouts, and provider metadata can require defaults or quarantine. skill rule
